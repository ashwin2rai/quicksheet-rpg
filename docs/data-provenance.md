# Data provenance

## Where data comes from

| Path | Content | Origin |
| --- | --- | --- |
| `data/core/*.json` | Classes, subclasses, features, ancestries, communities, domains, Level 1 domain cards, Tier 1 weapons and armor, Beastforms, starting items | Generated by `tools/import-og-dhsrd.mjs` from Old Gus' edited SRD (`scripts/og-dhsrd-features.js`) at the commit pinned in `data/srd-sources.lock.json`. The text is SRD 2.0 material, © Critical Role, LLC, used under the DPCGL. |
| `tools/curation/core.json` | Which upstream records are imported; QuickSheet's structured reading of each feature's, card's and gear feature's mechanics; corrections where Old Gus differs from the official SRD (`officialOverrides`, `nameCorrections`) | Original QuickSheet curation, reviewed against the official SRD 2.0 PDF |
| `data/flavor/*.json` | Names, pronouns, appearance details, personalities, motivations, hooks, Experience candidates, class style weights, companion animal/name suggestions, Orderborne sayings | Original QuickSheet content (`meta.source: "quicksheet-original"`) |
| `data/hope-fear/` | Hope & Fear expansion records | Empty until V3 |
| `data/srd-sources.lock.json` | Upstream URLs, commit, SHA-256 pins, review date | Maintained by hand |

Every game-data record has a `source` tag with these fields:
- `sourceSet`: `core` or `hope-fear`
- `sourceVersion`: `2.0`
- `reference`: where the record was taken from
- `pages`: Core Rulebook page and card references, as cited by Old Gus
- `errata`: whether errata applies

Record IDs are stable, namespaced slugs (`class.bard`, `feature.galapa.shell`, `card.book-of-ava`). Once published, an ID must not change, even if the display name changes.

## Importer

```sh
git clone https://github.com/callmepartario/og-dhsrd /tmp/og-dhsrd
git -C /tmp/og-dhsrd checkout <pinned commit>
npm run import:og -- /tmp/og-dhsrd          # rewrites data/core/*.json
npm run import:og -- /tmp/og-dhsrd --check  # exits 1 if committed data differs
```

The importer runs only the leading data section (array literals) of the upstream script, in an empty `vm` context with a timeout. It converts the small HTML vocabulary in the upstream data to Markdown and fails on any tag or entity it does not recognize. It also fails if a feature or gear feature has no curated mechanics entry, or if a curation entry matches nothing. No upstream code is copied into QuickSheet's runtime.

## Cross-check against the official SRD

`data/srd-sources.lock.json` pins the official SRD 2.0 PDF. In V1 every imported Level 1 text and number was compared with it (see RD-001 and RD-025 in `docs/rules-decisions.md` for results and corrections). To repeat the check after an upstream change:
1. Extract the PDF's text with any PDF-to-text tool.
2. Search it for each record's text and statistics.

An entry in `officialOverrides` must state its reason. The importer fails if an override matches no imported record.

## SRD Drift Check

`.github/workflows/srd-drift.yml` runs `tools/check-srd-drift.mjs` weekly and on demand. It is independent of CI and of any deployment. It fingerprints each source in the lock file:
- `sha256` mode: the raw bytes (Old Gus files, official SRD PDF, DPCGL PDF)
- `pdf-links` mode: the set of PDF links on the official SRD and license pages, so a changed download pointer counts as drift

Results:
- **Drift:** fails only that workflow, and writes a job summary with old and new hashes and next steps.
- **Network failure or block:** reported as inconclusive, never as unchanged.
- **Pins:** never updated automatically.

Scheduled workflows pause on inactive repositories, so use the manual "Run workflow" button as the fallback. `node tools/check-srd-drift.mjs --print-current` prints current fingerprints for a manual refresh.

## Refreshing upstream pins (manual review)

1. Fetch the new upstream version and run `npm run import:og -- <path> --check` to see which data files would change.
2. Read the upstream diff. Old Gus often makes editorial changes, so a changed hash does not necessarily mean the game rules changed.
3. Update `tools/curation/core.json` if mechanics changed. Re-run the importer, `npm run validate:data` and `npm test`. Review any snapshot changes before accepting them.
4. Update `data/srd-sources.lock.json` (commit, sha256, `lastReviewed`, `reviewNote`).
5. If the DPCGL text changed, read the new terms and update the attribution in `NOTICE.md`, `README.md` and `src/markdown.js` if needed.
